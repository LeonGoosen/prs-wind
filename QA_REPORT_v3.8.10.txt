CORRECTIONS TO THE PREVIOUS 11 FINDINGS
=====================================
1. Target and stage deletion: capture edits BEFORE removing array entries; do not
   read an old position-indexed form into the surviving objects afterward. DOM
   stage/target identity checks protect capture. Successful and failed deletions
   retain the correct survivor geometry and values, including after simulated
   reopening. Existing labels are preserved except the established automatic T1,
   T2 numbering behavior for generic target labels.
2. Rifle/ammo draft resume: reconnect the edited ammo object to its rifle and
   commit that same object. New ammunition name and MV survive resume/save/reopen.
3. Calibration A headings: blank headings retain their original column positions.
   Duplicate/unsupported edits are isolated as recoverable pending calibration;
   they do not silently reassign or drop stored measurements.
4. Correction-history growth: snapshots omit snapshot/history/draft containers,
   while each accepted correction records a single prior committed revision.
   Forty actual-control corrections passed; the one-stage fixture grew from
   5,878 to 49,988 serialized bytes. A separate
   helper-level 1,000-revision test passed within its bounds. The 1,000-revision
   test is NOT a claim of 1,000 physical-phone correction sessions.
5. Locked historical records: completed geometry cannot be changed through normal
   setup. Correction edits remain drafts until saved; simply opening or leaving a
   completed record does not rewrite it. Completed views, Reports, Dashboard and
   historical learning read the committed snapshot. Legacy raw discrepancies are
   retained for investigation rather than silently overwritten.
6. UI/export/import consistency: invalid working holds stay as explicit draft
   text instead of replacing validated magnitudes. Editing, completed-stage Save,
   actual generated export bytes and FileReader import paths are exercised.
7. Historical shape validation: malformed saved solution collections and snapshots
   are rejected before replacing active data; accepted data can render Reports.
8. Identity integrity: required identifiers, safe characters and uniqueness are
   checked within entity collections. Active and Trash cannot contain the same
   match ID. Restoring a colliding identity is guarded.
9. Calibration structure: header/row dimensions and duplicate axes are validated.
   B-distance insertion preserves values AND left/right information by distance.
10. Clearing optional trajectory factors resets to the documented interim mode;
    explicit zero factors remain visible and saved. Incomplete/negative factors
    are recoverable draft edits, not valid solver-derived weights.
11. Invalid numerical conditions: negative/invalid weights and optional physical
    inputs cannot produce a new recommendation. Searches remain bounded, and the
    tested valid-input prediction behavior is preserved.

ADDITIONAL HARDENING FOUND DURING THE LOOPS
=========================================
- Duplicate rows/headings or oversized calibration text no longer force a normal
  edit into an unrecoverable read-only state. The user can reopen and correct the
  draft while the prior valid matrix remains intact.
- Invalid wind, DOF, Kestrel and target geometry entries are separate draft values.
  The old authoritative value is not replaced, and a pending invalid edit blocks
  progression/prediction instead of silently using a stale call.
- Cleared calibration metadata is not replaced with invented default conditions.
- First-use normalization does not repeatedly resurrect deliberately empty work
  tables. The last-row deletion guard and calibration survivor behavior are tested.
- Corrupt/rejected saved copies can be exported under DATA as original data for
  investigation. They are clearly labeled REJECTED / REVIEW ONLY, not verified
  restorable backups. Exact byte preservation was checked for a rejected local
  JSON string. IndexedDB quarantine preserves the original structured object.
- Candidate parsing, recovery verification and import now use compatible numeric
  and structural contracts. A truthy but unrestorable pin is not valid protection.
  Total checkpoint failure blocks editing/deletion rather than pretending success.
- Explicit replacement quarantines numerically invalid database data as well as
  malformed local data before allowing replacement.
- Invalid observation/completion timestamps do not propagate NaN into weighting;
  unusable dated evidence is not promoted into trusted directional/learning weight.
- Read-only and protected-change guards remain in place across tested keyboard,
  import, deletion, archive/restore, duplicate and asynchronous conflict paths.

suspect tables against the original solver readings/backup. Rejected or already
oversized legacy saves are preserved/exportable for review; do not erase them to
force startup. This release does not fabricate missing historical measurements.
